## What is a Remote Backend?

A **remote backend** is used to store the Terraform state file (`terraform.tfstate`) in a remote location instead of locally.

### Why do we need it?
**Problem with local state:**

- Only on your machine ❌
- Not shared with team ❌
- Risk of conflicts ❌
- Not secure ❌

## Solution:

👉 Store state remotely (like AWS S3)

## S3 + DynamoDB (MOST COMMON SETUP)

### Important Requirements
- S3 bucket must exist
- DynamoDB table must exist

DynamoDB Table:

```bash
Primary key: LockID
```

1. S3 → Store State File

👉 S3 bucket stores:

```bash
terraform.tfstate
```

```bash
terraform {
  backend "s3" {
    bucket = "my-terraform-state-bucket"
    key    = "project/terraform.tfstate"
    region = "ap-south-1"
  }
}
```
#### What this does:
- Stores state in S3
- Accessible by team

2. DynamoDB → Lock State File

👉 Prevents multiple users from updating state at same time

🧾 Example:
```bash
terraform {
  backend "s3" {
    bucket         = "my-terraform-state-bucket"
    key            = "project/terraform.tfstate"
    region         = "ap-south-1"
    dynamodb_table = "terraform-lock"
  }
}
```

#### How Locking Works

Scenario:

- Dev1 → runs terraform apply
- Lock created in DynamoDB

- Dev2 → tries to run
- Blocked ❌

### “Why use S3 and DynamoDB in Terraform?”

“S3 is used to store the Terraform state file remotely, allowing team access and persistence, while DynamoDB is used for state locking to prevent concurrent modifications and avoid conflicts

1. What happens without DynamoDB?

Multiple users → conflict → state corruption ❌

2. Can we use only S3?

Yes, but not safe for teams ❌
