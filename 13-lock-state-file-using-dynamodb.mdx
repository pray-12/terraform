### VVP:

## What is a Remote Backend?

A **remote backend** is used to store the Terraform state file (`terraform.tfstate`) in a remote location instead of locally.

### What do you mean by state locking?

State locking means preventing multiple users from updating the state file at the same time. if one person is applying the changes, other person will not be able to apply the changes until the first person completes the changes in the aws console.

### Why do we need it?
**Problem with local state:**

- Only on your machine ❌
- Not shared with team ❌
- Risk of conflicts ❌
- Not secure ❌
- If multiple people are working with same state file, If two people apply the same command `terraform apply`, terraform gets confused &terraform will execute the latest command. Old terraform apply command will get overridded.

## Solution:

👉 Store state remotely (like AWS S3)

## S3 + DynamoDB (MOST COMMON SETUP)

### Important Requirements

- S3 bucket must exist [enable versioning]
- DynamoDB table must exist [A table in DynamoDB is a place where data is stored in key-value format.] [partition key is required- LockID ,tablesettings - DynamoDB Standard-IA[1availablity zone]]

DynamoDB Table:

```bash
Primary key: LockID
```

1. S3 → Store State File

👉 S3 bucket stores:

```bash
terraform.tfstate
```

```bash
provider "aws" {
  region = "ap-south-1"
}

terraform {
  backend "s3" {
    bucket = "my-terraform-state-bucket"
    key    = "project/terraform.tfstate"
    region = "ap-south-1"
    encrypt = true
    dynamodb_table = "terraform-lock" # DynamoDB table name
  }
}

resource "aws_instance" "terraform-lock" {
  ami = "ami-123456"
  instance_type = "t2.micro"
  tags = {
    Name = "terraform-lock"
  }
}
```

```bash
terraform init
terraform plan
terraform apply
```

#### What this does:

- Stores state in S3
- Accessible by team
- Prevents multiple users from updating state at same time
- Lock state file in DynamoDB

2. DynamoDB → Lock State File

👉 Prevents multiple users from updating state at same time

🧾 Example:
```bash
terraform {
  backend "s3" {
    bucket         = "my-terraform-state-bucket"
    key            = "project/terraform.tfstate"
    region         = "ap-south-1"
    dynamodb_table = "terraform-lock"
  }
}
```

#### How Locking Works

Scenario:

- Dev1 → runs terraform apply
- Lock created in DynamoDB

- Dev2 → tries to run
- Blocked ❌

### “Why use S3 and DynamoDB in Terraform?”

“S3 is used to store the Terraform state file remotely, allowing team access and persistence, while DynamoDB is used for state locking to prevent concurrent modifications and avoid conflicts

1. What happens without DynamoDB?

Multiple users → conflict → state corruption ❌

2. Can we use only S3?

Yes, but not safe for teams ❌
